## 今回修正した問題

- スタッフが旧 `attendees` API から非担当会場の参加者を取得できた。両名簿 API を担当会場に限定し、フォーム項目 API でも管理者専用項目を非表示にした。
- QR、名簿、メールリンクからの受付で会場判定が異なった。参加者に会場が割り当てられている場合は、その会場の選択をすべての受付経路で必須にした。
- 同時受付で敗れた要求が古い状態から結果を判定していた。受付・履歴・監査・結果取得を共通の D1 batch にまとめ、成功1件と重複1件を返すようにした。監査保存に失敗すると受付自体もロールバックする。[D1 batch のトランザクション仕様](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)に基づく。
- 受付取消と参加者キャンセルも、履歴・監査・定員カウントと状態変更が一緒に確定するようにした。
- 申込直後と当日登録の QR に Passkey 登録用のトークンを入れていた。新規発券は `ticketToken`（Passkey 登録用）と `qrToken`（受付専用）を分け、画面・メールの QR に受付専用値を使う。既存 `v1` チケットは受付の互換性を維持する。
- メールの本人確認リンクを並行して開くと複数のセッションを発行できた。セッション作成とリンク消費を一緒に確定し、一度だけ成功させる。
- Passkey 認証 challenge の消費を原子的に判定し、同じ認証応答による並行セッション発行を防いだ。不正な署名やカウンターの検証失敗は400応答にする。
- ブラウザの他オリジンからの更新要求と OAuth 同意を拒否する。
- viewer に名簿閲覧スコープを付与し、受付・CSV 出力は引き続き拒否する。
- 会場スタッフや主催者を割り当てた空の下書きを削除すると外部キー制約で失敗した。割当を含めて削除する。
- 日付・時刻の文字列表現の違いで申込期間、キャンセル期限、API トークン期限、集計期間が誤判定される箇所を修正した。
- CSV の数式として解釈される値を文字列として出力する。
- ログイン直後の組織 ID をレスポンスに含め、運営メンバーの読込に使えるようにした。
- 画面の重複受付結果に最初の受付日時と担当識別子を表示する。
- 日程調整では存在しない日付・24時の正規化を拒否し、参加不可の曜日へ日付をまたぐ枠を提案しない。

### 当日登録の権限と実機確認
