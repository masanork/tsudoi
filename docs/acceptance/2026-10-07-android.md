# Android 実機確認（2026-10-07 JST）

接続した Pixel 10 Pro、Android 17、Chrome 154.0.8037.126 で確認した。カメラ互換対応の検証対象は `fix/camera-qr-fallback`（main `0b391fd` を基点）。端末識別子、アカウント情報、Passkey の識別情報、QR の生値は記録しない。

ローカル環境の Passkey 作成は、本番サービスの既存 Passkey によるログイン確認を代替しない。iPhone/Safari も未確認。

## 自動テストとの区別

デスクトップ Chromium のブラウザ受入テストでは、実際の QR PNG を canvas の映像ストリームへ渡し、native API がない、QR に未対応、初期化失敗、読取失敗の各ケースを検証した。QR 確認処理中の次フレーム待機、同じ QR の重複送信抑制、カメラ許可待ちで停止した後の遅延 stream の終了、権限拒否も検証する。これは実カメラの焦点・照明・端末権限・印刷品質の確認を代替しない。

## 再接続後の手順

1. 専用の新しいローカル DB と USB の localhost 転送を使い、実 Passkey で再ログインする。本番の参加者や既存イベントは変更しない。
2. 氏名のみで当日登録し、PNG の紙 QR を発行する。Mac に表示した検証用 QR を端末の実カメラで読む。
3. 同じ QR を受付・入退館・複数の配布回で使い、続けて映した場合の重複抑制と停止・再開を確認する。
4. native QR API を無効にした検証タブでも同じ実映像を読めることを確認する。
5. 会場の情報を準備して通信を切り、再読み込み・カメラ読取・未同期記録の保持・復旧後の同期を確認する。
6. 専用環境の端末保存を消去し、USB 転送とローカルサーバーを終了する。物理印刷と別の物理端末を使う訓練は別に記録する。
