# 日程調整から確定通知まで

## 目的と体験

日付の候補は従来どおり日単位の ○・△・× で回答する。リンクを知る人が共通の会話で時刻や場所を相談し、主催者が日付、開始・終了時刻、場所、補足を確定する。確定ページに最新の内容を表示し、カレンダーに追加できるようにする。確定後の変更も同じページに反映する。

会話はリンクを知る人全員に見える。入力欄にそのことと、機微な情報を書かないよう明示する。主催者は投稿を削除できる。公開投稿は文字数・頻度を制限する。日程調整を使わないイベントやアーカイブ済みイベントには公開しない。

## 通知

参加者が明示的に希望し、端末で許可した場合に、その端末に日程確定・変更を Web Push で知らせる。チャットの投稿では通知しない。通知文は内容を含めず、タップすると確定ページを開く。参加者は解除できる。iPhone / iPad ではホーム画面への追加が必要なことを案内する。

管理画面に通知登録数を表示する。登録数は人数・配達数・既読数を意味しない。未登録者や通知が届かない人には、主催者が確定ページのリンクを別途共有する。確定は通知サービスの可用性に依存させず、送信失敗や期限切れの購読を扱う。

## 実装上の確認事項

- イベントの確定内容と通知対象の記録を一貫して保存し、同時確定・再送・変更の競合を扱う。通知の外部送信は重複や失敗が起こり得る。
- 公開購読 API を任意 URL への送信に使われないよう、Push サービスの送信先を検証する。購読情報と VAPID 秘密鍵を公開・ログ出力しない。
- ローカル時刻とイベントのタイムゾーン、日付をまたぐ終了時刻、夏時間の曖昧・不存在時刻を検証する。既存の日時付き MCP 候補と iCalendar の互換性を保つ。
- 既存のオフライン受付用 Service Worker と共存し、通知クリックで対象イベントを開く。購読解除は他イベントの購読を壊さない。
- 確定前・確定後・変更・削除・権限境界を Worker / D1 とブラウザで検証する。実 Push 配達と iPhone / Android 実機は別途確認する。
