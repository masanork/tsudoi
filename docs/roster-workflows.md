# 名簿の項目・出力・連絡・再利用

## 実装範囲

- 管理者が申込項目の名称、選択肢、必須、公開範囲、表示順を変更し、廃止・再開する。項目IDと回答は保持する。項目キーと型は変更しない。
- 使用済みの選択肢は削除しない。別の分類に切り替える場合は新しい項目を追加し、旧項目を廃止する。必須の追加は過去の未回答を自動補完しない。
- 廃止した項目は新しい申込・当日登録・CSV取込の対象から外す。過去の回答は名簿の列設定から表示でき、全項目CSVにも残す。
- 名簿の表示列・順序は利用者とイベントごとにサーバーへ保存する。氏名は常に表示する。管理者専用項目の回答はスタッフ・閲覧者へ返さない。
- CSVは適用済みの検索・登録状態・申込経路・会場・チケット状態で絞り込み、未表示のページも出力する。全項目と表示列を選べる。所属も検索対象に含める。
- 全項目CSVの既存7標準列は維持する。表示列CSVではチケット状態を追加できる。CSVの数式対策と管理者限定、出力項目・件数・条件の監査を維持する。
- 日程調整を使わないイベントでも案内メールを作成する。送信前に有効な参加者のユニークなメール宛先件数を確認する。本文の修正後は宛先を確認し直す。表示は「送信予約」とし、配達完了とは区別する。
- 組織内の項目テンプレートを保存・追加・削除する。保存対象は有効な項目定義のみで、参加者・回答を含まない。追加先で新しい項目IDを発行する。同じキーがある場合は全体を中止する。
- 名簿で選択した100人までの所属・会場・カスタム回答を一括更新する。項目は一度に1種類ずつ画面から指定する。空欄は消去として確認し、必須回答の消去は拒否する。氏名・メール・チケット状態は一括変更しない。

## 競合・権限・監査

項目・列設定・参加者のリビジョンを照合する。項目編集と一括更新は、状態と変更前後の監査を同じD1 batchで確定する。監査失敗時は状態を残さない。一括更新は固定数のSQLとJSONパラメーターを使い、人数・回答数に比例してSQLを増やさない。

一括更新は、対象者の1人でも他イベント・古いリビジョン・受付済みの会場変更に該当する場合、全員の更新を中止する。検証後に項目が変更・廃止された場合も中止する。再送で重ねて変更しない。競合した場合は名簿を再取得し、対象者と変更内容を確認する。

テンプレート・項目変更・一括更新は管理者のブラウザーセッションに限定する。既存の項目作成・CSV出力・案内メールAPIのスコープ付き外部連携は維持する。

## 配置

既存DBでは `0008_roster_workflows.sql` を適用してからコードを配置する。既存migrationは変更しない。新規DBでは `0001`〜`0008` を順に適用する。新しいテーブルは列設定とテンプレートで、既存の参加者・チケット・回答は書き換えない。

この変更だけで本番反映・実メール到達・実端末での運用を確認済みとはしない。

2026-10-21に `0008` を適用して本番へ配置した。配置version、追加スキーマ、新APIの確認と残る実機確認は[本番反映記録](releases/2026-10-21-roster-workflows.md)を参照する。
